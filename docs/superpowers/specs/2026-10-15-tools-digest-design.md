# Спека: дайджест бесплатных инструментов для вайбкодеров (`/tools`)

Дата: 2026-10-15 · Статус: на утверждении
Основание: редакторская инструкция «Дайджест бесплатных инструментов для вайбкодеров» (разделы 1–11).

## 1. Цель

Отдельная команда бота `/tools [часы]` собирает короткий дайджест бесплатных инструментов, которые русскоязычный вайбкодер может попробовать сам: конструкторы приложений, CLI-утилиты, расширения, скрипты автоматизации, файловые утилиты, браузерные инструменты, локальный AI, дизайн-инструментали. Не только AI-сервисы.

Главный критерий: **понятная практическая польза**, а не «AI в позиционировании». Команда работает по запросу редактора, ничего автоматически не публикует; `TELEGRAM_AUTO_SEND` её не гейтит (как `/digest` и `/card`).

## 2. Источники (все keyless)

Заново используем из `news_pipeline.py`:
- `fetch_hackernews` — акцент на посты вида «Show HN» (титул начинается с «Show HN»);
- `fetch_github_trending` (API ossinsight.io, min_stars ≥ 5);
- `fetch_hf_trending` (модели/spaces/datasets);
- `fetch_reddit` — расширенный список сабов: LocalLLaMA, opensource, SideProject, vibecoding, ClaudeAI (новые: opensource, SideProject).

Новые источники в `news_pipeline.py` (с тем же контрактом «никогда не бросает исключение, возвращает список»):
- `fetch_producthunt` — RSS Product Hunt, тот же URL, что уже есть в `editorial.py` (`/feed?category=artificial-intelligence`); вынесем константу в `news_pipeline`, чтобы editorial и tools жили от одной;
- `fetch_dev_to` — RSS `dev.to/feed/tag/ai` (+ тег `ai tools`);
- `fetch_awesome_lists` — raw README с GitHub по фиксированному списку каталогов: `taskade/awesome-vibe-coding`, `yeaight7/awesome-ai-devtools`; парсим markdown-строки со ссылками (`- [name](url) — desc`); каждая запись — кандидат с источником «Awesome: <имя каталога>».

Существующие `source_health`-метрики и `fetch_rss_feed` применяются и к новым лентам (health для Product Hunt / DEV.to / awesome).

Часовое окно по умолчанию — 168 ч (у инструментов медленный новостной цикл); аргументом `/tools N` — любое 6–720 с шагом 1, обрезается как в `/digest`.

## 3. Конвейер (`tools_digest.py`, новый модуль)

```
collect_tools(hours) → dedup_cross_source → filter_seen
  → fetch_official_page (первоисточник каждого кандидата)
  → select_tools(candidates, client)    # один AI-вызов
  → render_tools() + editor notes       # 3 сообщения боту
```

1. **collect_tools(hours)** — как `editorial.collect_topics`: слияние источников → `dedup_cross_source` → keyword-фильтр (расширенный список ключей инструментов: «CLI», «extension», «плагин», локально, конструктор, converter и т.п.) → кап ~40 кандидатов (по keyword-баллу).
2. **fetch_official_page(cand)** — полнотекстовая экстракция офиц. страницы/README (`extract_full_text` из `news_pipeline.py`), для GitHub — доп. README + лицензия + дата последнего релиза через API GitHub (keyless, без токена — лимитов хватит на ≤ 40 запросов). Всё с таймаутами; неудачные проверки НЕ отбрасывают кандидата, а помечают `uncertain`.
3. **select_tools(candidates, client)** — один вызов Groq `gpt-oss-120b` (`reasoning_effort="low"`; без ключа — режим без AI, см. §7). Вход: список кандидатов (url, title, source, даты, текст первоисточника ≤ 1500 знаков). Выход — строго JSON:
   ```json
   {"title": "...", 
    "items": [{"name", "url", "category", "platforms", "free_tier",
               "desc", "limits", "proof_url", "why", "verdict": "ok|uncertain|wrong"}],
    "notes": "..."}
   ```
   Правила из инструкции зашиты в системный промпт: 3–5 инструментов, разнообразие категорий (не 5 однотипных конструкторов), приоритеты (неочевидные находки, бесплатные альтернативы платных, «применить сразу», релизы, open-source), запрет рекламных формулировок и штампов (`_NATURAL_TEXT_RULES`), запрет категоричных заявлений о бесплатности/ОС/офлайн без подтверждения. `verdict=wrong` отсеивается кодом, `uncertain` остаётся с пометкой «требует уточнения».
4. **render_tools(result)** — три блока:
   1) «источники проверки» — список `proof_url` + url кандидата;
   2) готовый пост для Telegram (отдельным сообщением, для копирования) — заголовок + пункты формата `› Название [платформы] — описание (1–2 предложения)` с прямой ссылкой на название + ограничение, если существенное; html-эскейп всего; разбиение > 4096 — `_split_by_paragraphs`;
   3) примечания: статус каждого пункта (проверен / требует уточнения), ограничения, модель бесплатности, причина включения; если проверенных < 3 — явная строка «подходящих инструментов недостаточно» и вывод только проверенных.

`wrong`-пункты из поста убираются (как в `fact_check_digest`).

## 4. Команда и кэширование (`bot.py`)

- `/tools` — 168 ч; `/tools 24` — окно 24 ч. Промежуточный статус сразу («собираю инструменты…»), результат через 1–3 минуты.
- Кэш результата последнего прогона в `bot_data["tools_cache"]`: повторный `/tools` без аргумента возвращает кэш; `/tools N` с другим окном — пересбор.
- `bot_data["tools_seen"]` — url уже показанных инструментов; исключаются из следующих сборов (как `editorial_seen_cards`).
- Не отправляет в Telegram канал — только в чат с ботом.

## 5. Дедупликация и качество

- `dedup_cross_source` склеивает дубли одного инструмента; счётчик `buzz` для новостей (`_is_hot` в `notifier.py`) не трогаем — он к инструментам не применяется.
- Лимиты: ≤ 5 пунктов (DIGEST-подобный кап), ≤ 40 кандидатов на AI, ≤ 1500 знаков текста на кандидата.
- Ошибки AI на прогоне целиком → фолбэк: список «голодных» кандидатов (название + ссылка + однострочник из README) без описаний, с пометкой «режим без AI».
- Новые сборщики не могут ронять команду: try/except на каждый, ноль = просто без этой ленты (как в editorial).

## 6. Тесты (`tests/test_tools_digest.py`)

- парсер awesome-README (`fetch_awesome_lists` на фиксированном markdown);
- `select_tools` на фейк-клиенте: парсинг JSON, отсев `wrong`, сортировка разнообразия категорий, кап 5;
- фолбэк без `GROQ_API_KEY` (голые кандидаты, пометка);
- `render_tools`: эскейп HTML в названиях/описаниях/proof_url, лимит 4096, блок «недостаточно проверенных»;
- `/tools` в `test_bot.py`: кэш повторного вызова не делает второй AI-вызов; `tools_seen` фильтрует.

## 7. Системные ограничения

- Без `GROQ_API_KEY` — как §5-фолбэк: механический список, без AI-описаний и «proof»-проверки (пометка).
- GitHub API без токена: 60 req/h на IP — достаточно (≤ 40 кандидатов + 2 каталога), при 403 кандидаты получают `uncertain`, не отбрасываются.
- Продукт Hunt RSS — только публичный фид, без токенов. При деградации ленты — `source_health` и просто меньше кандидатов.
- Модель бесплатности: только 5 категорий из раздела 5 инструкции; «полностью бесплатный» присваивается только при подтверждении из первоисточника.
