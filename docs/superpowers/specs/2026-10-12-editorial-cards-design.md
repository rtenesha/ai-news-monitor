# Дизайн: карточки для редактора (`editorial.py` + `/digest` в боте)

Дата: 2026-10-12
Статус: черновик на ревью

## Зачем

Нынешний дайджест («📊 Дайджест к этому часу») отдаёт контент-менеджеру почти готовые
посты, но отбор остаётся одномерным (score 0–5 по ключевым словам + AI) и не даёт
материала для решения «что публиковать»: нет оценки по критериям, рубрики,
фактчекинга по полям, черновика в нужном формате. Редакторская инструкция задаёт
другой контракт: парсер собирает → AI-оценивает и проверяет → человек решает.

Результат этой работы: у контент-менеджера появляется команда `/digest` в боте,
которая выдаёт список отобранных тем, и `/card <№>` — полная редакторская карточка
по документу (§8) с черновиком публикации. Автоотправка остаётся выключенной
(`TELEGRAM_AUTO_SEND`).

## Целевой UX

- **`/digest`** — компактный список тем за окно (по умолчанию 24ч; `/digest 48`
  расширяет окно до 48ч):

  ```
  📋 Темы к рассмотрению (24ч)

  1. [11/12 · Инструменты] Claude научился ставить себе скилы сам
     📄 карточка: /card 1
  2. [8/12 · Новое в ИИ] …
     📄 /card 2
  …

  Резерв (6–8): темы 4, 5. Приоритет (9–12): темы 1, 2, 3.
  ```

- **`/card <№>`** — полная карточка, 1–2 сообщения Telegram (лимит 4096 символов).
  Черновик публикации — отдельным сообщением, чтобы его можно было скопировать
  одним действием.

## Источники

| Источник | Как | Статус |
|---|---|---|
| OpenAI Blog, Google AI Blog, DeepMind Blog, HuggingFace Blog | feedparser (`fetch_rss_feed`) | уже есть |
| Hacker News | Firebase API, score ≥ 100 | уже есть |
| GitHub Trending | api.ossinsight.io, Python/TS/All, min_stars ≥ 5 | уже есть |
| Product Hunt (тема AI) | RSS `producthunt.com/feed?category=artificial-intelligence` | **новый** |
| GitHub Blog | RSS `github.blog/feed/` | **новый** |
| Hugging Face trending | `https://huggingface.co/api/models?sort=trendingScore&limit=20` и `huggingface.co/api/spaces?sort=trendingScore` — без ключей; забираем название, описание, ссылку, звёзды, `lastModified` | **новый** |

Новые фетчеры идут через `fetch_rss_feed` (PH, GH Blog — RSS) или напрямую
`urllib` с существующим `timeout` и health-трекингом (HF API — JSON). Каждая запись
приводится к общему виду карточки статьи: `title`, `url`, `summary`, `source`,
`published`. HF trending не привязан к календарю «за 24ч» у записи — считаем окном
запроса, в карточке это отмечается ограничением («трендинг на момент сбора»).

**Не входят** (осознанно, решено с редактором): Zerocoder RSS, Google News, ZDNet,
Simon Willison, Reddit, Telegram-каналы, arXiv/Papers with Code (отложено отдельным
заходом — там нужен свой промпт отбора научных тем).

**Старые системы не трогаются**: `monitor.py` и рутина 9:00 продолжают работать
со своим списком лент, включая вычеркнутые выше. `notifier.py` и рутина каждые
2ч остаются молчать (рубильник `TELEGRAM_AUTO_SEND` выключен). Двухчасовая рутина
продолжит писать дайджест в лог — это можно оставить как дешёвый «черновой» пульс
или позже заменить запуском карточек; в скоуп этой работы не входит.

## Конвейер `/digest`

```
сбор источников → dedup_cross_source → keyword-фильтр → кап
→ score_topic_ai() (редакторская оценка, структурированный JSON)
→ дедуп по смыслу среди кандидатов → сортировка по сумме баллов
→ список тем (кэш в памяти) → /card № → карточка
```

### Шаг 1. Сбор и предфильтрация

Все источники из таблицы → `news_pipeline.dedup_cross_source()` (склейка дублей
одного события с разных лент) → keyword-фильтр (списки `KEYWORDS` из
`editorial.py`, копия текущих, чтобы не менять поведение `monitor`/`notifier`) →
кап 15 кандидатов (сначала по keyword-весу, HIGH_VALUE × 2) — чтобы не сжигать
квоту Groq на мусор.

### Шаг 2. Редакторская оценка — `score_topic_ai()`

Один структурированный AI-вызов на статью (модель `openai/gpt-oss-120b`,
`reasoning_effort="low"`, тот же клиент из `news_pipeline`). Выдаёт JSON:

```json
{
  "criteria": {"новизна": 2, "польза": 2, "удивление": 1,
               "актуальность": 2, "пересылка": 1, "соответствие_аудитории": 2},
  "total": 10,
  "rubric": "Инструменты",
  "format": "Б",
  "one_liner": "Claude Code научился ставить скилы сам — без ручных папок"
}
```

Критерии и веса (0–2 каждый, максимум 12): новизна, польза для читателя,
удивление («так можно было?!»), актуальность (горит ли сейчас), пересылаемость,
соответствие аудитории (ИИ и вайбкодинг). Пороги: **9–12 — приоритет**,
**6–8 — резерв**, **0–5 — отброшено**.

Рубрики (8, из документа): «Новое в ИИ», «Инструменты и приложения», «Хаки и
лайфхаки», «Промты и скилы», «Ресёрч и демо», «Industry/рынок и деньги»,
«Обучение и навыки», «Инфоповод-пустышка» (последняя — для отсева; сюда
попавшее отбрасывается).

Форматы: **А** — короткая новость/перевод, **Б** — обзор с деталями и выводом,
**В** — туториал / пошаговый разбор, **Г** — подборка (список), **Д** — «так
можно было?!» (делимся лайфхаком от лица канала), **Е** — реакция/мнение.
AI предлагает формат, редактор в карточке может передумать и попросить черновик
в другом (вне скоупа — меняется правкой константы).

Фолбэк без `GROQ_API_KEY` или при ошибке AI: тема получает `total = keyword score`
(0–5 из keyword-веса, помечается «оценка без AI»), рубрика «не определена». В этом
режиме порог списка ослабляется до топ-8 по keyword-баллу ≥ 1 — иначе весь список
был бы пуст; список помечается «режим без AI, оценки приблизительные». `/card` в
фолбэке отдаёт усечённую карточку из метаданных статьи (без AI-полей и без
черновика).

Ошибка Groq/битый JSON на конкретной статье → статья падает в фолбэк-оценку, остальные
продолжаются (не «всё или ничего»).

### Шаг 3. Отбор в список

Темы сортируются по `total` (при равенстве — новее раньше), показываются только
total ≥ 6 (резерв и приоритет). Максимум 8 позиций в списке. В памяти процесса
хранится: словарь `n → article + result score_topic_ai`; повторный `/digest`
пересобирает список за то же окно.

### Шаг 4. Карточка — `build_card(article, score_result, client)`

Один AI-вызов на карточку (контекст: полнотекстовая выборка `news_pipeline.extract_full_text`
+ результат скоринга). Выдаёт JSON по полям документа:

| Поле | Источник |
|---|---|
| Заголовок темы | AI |
| Рубрика | из скоринга (редактор может поменять в диалоге — вне скоупа) |
| Краткое содержание | AI, 2–4 предложения |
| Почему интересно | AI |
| Для кого полезно | AI |
| Дата публикации | из метаданных источника |
| Дата события | при невозможности достоверно — совпадает с датой публикации, помечается ограничением |
| Первоисточник | ссылка статьи + `«📎 Оригинальный пост»` для твитов (то же правило, что в дайджесте) |
| Доп. источники | веб-корроборация `fetch_google_news` (см. шаг 5) — ссылки на 1–3 независимые публикации |
| Подтверждённые факты | фактчекинг (шаг 4б) |
| Что требует проверки | фактчекинг (шаг 4б) |
| Ограничения и риски | AI (что может быть маркетингом, что не проверено) |
| Оценка интересности | 6 критериев + сумма из скоринга |
| Предлагаемый формат | формат из скоринга |
| Три варианта заголовка | AI: информативный / польза / любопытство |
| Черновик публикации | AI по стилю канала (шаг 4в) |
| Визуальная идея | AI, одна фраза |
| Статус | всегда `черновик — на утверждении`; заполняет человек |
| Причина отклонения | заполняет человек; парсер только оставляет пустым |

**4б. Фактчекинг на карточку** — переиспользует механику `notifier.py`
(`_parse_factcheck_json`, логика вердиктов и корроборации) импортом из него,
без переезда в `news_pipeline` — рабочий дайджест не трогаем. AI перечисляет
утверждения черновика и возвращает
для каждого `ok / uncertain / wrong`; `wrong`-утверждения выбрасываются из текста
черновика, `uncertain`-формулировки переписываются только из подтверждённого.
черновик не генерируется. Результат раскладывается в поля «Подтверждённые факты» /
«Что требует проверки». Корроборация: до 2 запросов `fetch_google_news` на карточку (по запросам от AI) —
найденные ссылки кладутся в «Доп. источники»; тишина = не блокер.

**4в. Черновик публикации** — на тот формат, что предложил скоринг; стиль:
`_NATURAL_TEXT_RULES` + правила §7 документа (не дробить абзацы, без эмодзи в каждой
первой строке, без искусственного хайпа и пассивных CTA). Заголовок — короткий,
до 10 слов, эмодзи в конце, конкретный результат или эффект открытия. CTA — лёгкий
вопрос, выбран из готового набора. Черновик НЕ отправляется сам — он лежит внутри
карточки, которую человек сам решит скопировать в канал.

### Шаг 5. Хранение и дедуп

- Карточки живут в памяти процесса бота (словарь `n → card`), живут до перезапуска.
  Полный `/digest` за окно пересобирается заново по команде, так что пропущенные
  карточки восстанавливаются пересборкой.
- Дедуп между окнами: карточка с тем же URL (после `normalize_url`) не пойдёт в
  список повторно, если по этому URL уже строили карточку в этой сессии
  (счётчик в `bot.py`-состоянии).
- Никакой записи на диск, никакого статуса «опубликовано» — решение остаётся за
  человеком в Telegram-диалоге.

## Ошибки и деградация

- Нет `GROQ_API_KEY` → `/digest` работает на keyword-баллах, помечает «оценка без
  AI», `/card` отдаёт усечённую карточку без AI-полей и черновика.
- AI-вызов упал / JSON не распарсился → эта тема со сниженной оценкой, остальные
  работают; карточка конкретной темы недоступна → «не смог построить карточку,
  попробуй позже».
- Источник не отвечает → health-трекинг уже есть в `fetch_rss_feed` и уронит
  только его; `/digest` строится из того, что пришло.
- `/card` без номера / вне списка → приглашение вызвать `/digest` сначала.

## Безопасность и лимиты

- HTML-экранирование всё, что попадает в пост (заголовки, тексты, URL — как в
  дайджесте: `html.escape(..., quote=True)` для href и текста; фолбэк на plain-text
  при отказе Telegram).
- Квота Groq: `/digest` = 1 вызов на кандидата (≤15), `/card` = 1–2 вызова на
  тему; повторный вызов — по решению человека.
- `/digest`/`/card` доступны всем, кто найдёт бота — как уже работают `/news24`,
  `/post` (известное наблюдение аудита «нет allowlist» остаётся открытым и решается
  отдельной задачей, не здесь).

## Тестирование (TDD, мок Groq как в существующих тестах)

- `score_topic_ai`: парсинг JSON, границы критериев (0–2), сумма, пороги,
  фолбэки на битый JSON/исключение.
- Отбор: сортировка, отсев < 6, лимит 8, дедуп по URL между окнами.
- `build_card`: сборка полей, фактчекинг-раскладка (ok/uncertain/wrong → поля),
  экранирование HTML, лимит 4096 (разбивка на 2 сообщения: карточка + черновик).
- Фетчеры PH/GH Blog/HF trending: мок urlopen, нормализация записи, отказ
  источника не валит остальных.
- UX бота: `/digest` без карточек → подсказка; `/card 999` → «нет такой темы».

## Вне скоупа (решено с редактором / YAGNI)

- Статистика публикаций Zerocoder в оценке — TODO отдельного захода, когда будет
  выгрузка канала (упомянуто редактором как «со временем»).
- Правки `monitor.py` / удаление источников из старых систем — не здесь.
- Публикация в канал из бота (кнопка «опубликовать») — скип: отправка каналу
  требует прав бота на сам канал, а человек и так публикует сам.
- arXiv, Papers with Code, allowlist для бота — отдельные задачи.
