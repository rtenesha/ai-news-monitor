# news_pipeline.py: улучшение отбора новостей (идеи из Horizon)

## Контекст и проблема

Изучили клонированный в проект репозиторий [Horizon](https://github.com/Thysrael/Horizon) (`Horizon/`) — зрелый мультиисточниковый агрегатор новостей на Python. Сравнили с нашим ботом (`monitor.py`, `notifier.py`, `bot.py`) и выбрали, что из его подхода стоит перенести.

Ключевая проблема, названная пользователем: **«много шума, мало источников»**.

Конкретные причины:
- AI-скоринг судит только по title + RSS-сниппету (обрезанному summary из ленты), без текста самой статьи — оценка часто не отражает реальную важность.
- `monitor.py` парсит ответ AI как одну строку свободного формата на весь батч статей (`[N] SCORE | SUMMARY`) — при сбое парсинга скор статьи теряется.
- `notifier.py` вообще не использует AI для отбора «горячих» новостей — только подсчёт ключевых слов, из-за чего формальные совпадения без реальной значимости проходят наравне с важными.
- Нет кросс-источниковой дедупликации: одна и та же новость с разных RSS-лент (например ZDNet и Forbes про один и тот же релиз) попадает в дайджест/алерты дважды.
- Всего 10 RSS-лент, нет источников с широким и постоянным охватом трендов (Hacker News, GitHub Trending, поиск по Google News).

## Ограничения

- Облачные рутины (`monitor.py`/`notifier.py`) в проде скачиваются через `curl` отдельных `.py`-файлов из GitHub, не `git clone` (блокируется в облаке Anthropic). Сейчас рутины выключены (используется только `bot.py` on-demand), но решение должно оставаться совместимым с curl-деплоем на случай, если их снова включат.
- Никаких новых платных сервисов/ключей — используем только keyless API (Hacker News, OSS Insight, Google News RSS) и уже существующий бесплатный Groq.
- `KEYWORDS`/`HIGH_VALUE` остаются продублированными в `monitor.py` и `notifier.py` (тематический словарь, специфичный для каждого файла) — это единственное, что продолжает дублироваться по существующему правилу из CLAUDE.md.

## Решение: общий модуль `news_pipeline.py`

Вся новая инфраструктурная логика (фетчеры новых источников, full-text экстракция, дедупликация, структурированный AI-скоринг) выносится в один новый файл `news_pipeline.py`, который импортируют и `monitor.py`, и `notifier.py`. Если рутины в облаке будут снова включены, `curl` должен будет скачивать этот файл вместе с остальными — раздел «Автоматические рутины» в CLAUDE.md обновляется соответствующей командой.

```
news_pipeline.py
├── fetch_hackernews(min_score=100) -> list[dict]
├── fetch_github_trending(languages, min_stars=5) -> list[dict]
├── fetch_google_news(query, hours=24) -> list[dict]
├── extract_full_text(url) -> str | None
├── dedup_cross_source(articles) -> list[dict]
├── dedup_semantic(articles, groq_client) -> list[dict]
└── score_article_ai(article, full_text, groq_client) -> AnalysisResult
```

Все фетчеры возвращают статьи в том же формате, что уже используется в пайплайне: `{"title", "url", "summary", "source", "published"}` — остальной код (`filter_by_keywords`, форматирование сообщений и т.д.) не меняется.

### Новые источники (все keyless)

- **Hacker News** — `hacker-news.firebaseio.com/v0/topstories.json` → топ-30 историй → фильтр `score ≥ min_score` (по умолчанию 100). `source="Hacker News"`.
- **GitHub Trending** — `api.ossinsight.io/v1/trends/repos?period=past_24_hours&language=...` для языков `["Python", "TypeScript", "All"]`, `min_stars=5`. `title` = `"{repo} (+N⭐ за 24ч)"`, `summary` = описание репозитория, `url` = `github.com/{repo}`, `source="GitHub Trending"`. Дополнительно фильтруется по нашим ключевым словам (ИИ/вайбкодинг), чтобы не тащить нерелевантные трендовые репозитории.
- **Google News RSS search** — `news.google.com/rss/search?q=...&when:Nh` через `feedparser`, отдельный запрос на каждый пункт из небольшого списка тематических запросов (например `"вайбкодинг"`, `"Claude Code"`, `"AI coding agent"`). `source="Google News: {query}"`.

Добавляются в `fetch_all_sources()` обоих скриптов рядом с текущим RSS-фетчем.

### Full-text экстракция

`extract_full_text(url)` переиспользует уже работающий в `bot.py` (`fetch_url_article`) паттерн запроса (`urllib` + существующий `_BROWSER_UA`, таймаут 15с), но извлекает тело статьи через `trafilatura.extract()` вместо грубой regex-чистки — вырезает именно текст статьи без меню/рекламы/комментариев.

Вызывается **только для статей, прошедших keyword-фильтр** (баланс точности и стоимости/скорости — не для всего сырого потока). Если `trafilatura` не смогла извлечь текст или он короче ~200 символов (JS-сайт, пэйвол, блокировка) — тихий откат на RSS `summary`, скоринг не блокируется.

### Структурированный AI-скоринг

```python
class AnalysisResult(BaseModel):
    score: int = Field(ge=0, le=5)
    reason: str
    summary: str
```

Один Groq-вызов (`llama-3.3-70b-versatile`) на статью, промпт — тот же смысл, что сейчас в `monitor.py` (аудитория Zerocoder: ИИ и вайбкодинг), но на вход full-text вместо сниппета, ответ — JSON-объект вместо свободной строки `[N] SCORE | SUMMARY`. Ретраи — `tenacity`, `stop_after_attempt(3)`. При провале всех попыток — фолбэк на текущий чисто keyword-based `score_article()`.

Заменяет batch-парсинг в `monitor.py` и добавляет AI-скоринг в `notifier.py`, где сейчас его нет вообще (там только keyword-подсчёт).

### Дедупликация

**URL-дедуп** (`dedup_cross_source`) — сразу после сбора статей со всех источников, до скоринга. Нормализация: нижний регистр хоста, без `www.`, без trailing slash, без трекинг-параметров (`utm_*`, `fbclid`, `gclid` и т.п. — список параметров как в Horizon). При коллизии оставляем статью с более длинным `summary`, `source` объединяется через `+`.

**Семантический AI-дедуп** (`dedup_semantic`) — после порогового AI-скоринга, только над уже отобранными важными статьями. Один batched Groq-вызов: пронумерованный список `[i] заголовок + summary` → модель возвращает JSON `{"duplicates": [[keep_idx, dup_idx, ...], ...]}`. В каждой группе оставляем статью с наивысшим `ai_score`, остальные отбрасываем. При ошибке AI-вызова или невалидном JSON — шаг тихо пропускается.

Включается в обоих скриптах.

## Отказоустойчивость

- Каждый новый фетчер обёрнут в try/except → при ошибке возвращает `[]`, не валит весь прогон (как уже сделано для отдельных RSS-лент).
- `extract_full_text` — тихий откат на RSS summary при неудаче.
- AI-скоринг и семантический дедуп — при ошибке Groq откатываются на keyword-поведение, расширяя существующий в CLAUDE.md принцип фолбэка «нет `GROQ_API_KEY` → работаем на чистом keyword-скоринге».

## Стоимость

Главный рост нагрузки: `notifier.py` (каждые 2ч) начинает делать один AI-вызов на скоринг **на каждую** статью, прошедшую keyword-фильтр — раньше таких вызовов не было. Вызовы последовательные (не параллельные), чтобы не упереться в rate limit бесплатного тарифа Groq — как уже сделано в `monitor.py`.

## Проверка

Автотестов в проекте нет. План проверки:
1. `extract_full_text` и URL-нормализация — чистые функции, добавляем несколько inline smoke-проверок (пара реальных URL с utm-метками → один и тот же нормализованный ключ).
2. Ручной прогон `python3 monitor.py` и `python3 notifier.py` локально — сверяем консольный вывод (сколько статей с каждого источника, сколько отсеялось дедупом, AI score по каждой статье).
3. Ручная сверка 3-5 отобранных статей с оригиналом по ссылке — как уже принято в проекте (риск галлюцинации фактов, описанный в CLAUDE.md).

## Вне рамок этой итерации

- Twitter/Reddit-скрапинг как постоянные источники (пока остаётся on-demand `/reddit` в `bot.py`).
- Мультипровайдерный AI-клиент (Anthropic/OpenAI/Gemini и т.д.) — остаёмся на Groq.
- Балансировка дайджеста по категориям-квотам, второй AI-проход обогащения (background knowledge) — не запрашивались, не добавляем.
