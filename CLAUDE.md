# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Автоматический мониторинг ИИ-новостей для контент-менеджера Telegram-канала **Zerocoder** (тематика: ИИ и вайбкодинг). Два режима работы:

- **`monitor.py`** — ежедневный дайджест в 9:00 МСК, отправляется в Telegram
- **`notifier.py`** — каждые 2 часа один пост «📊 Дайджест к этому часу»: до 5 горячих новостей кратко, с фактчекингом перед отправкой

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env  # заполнить ключи

python3 monitor.py        # дайджест за последние 24ч
python3 monitor.py 48     # дайджест за 48ч
python3 notifier.py       # собрать дайджест горячих новостей за 24ч (запускается каждые 2ч)
```

## Переменные окружения (`.env`)

| Переменная | Где взять |
|---|---|
| `GROQ_API_KEY` | console.groq.com (бесплатно) |
| `TELEGRAM_BOT_TOKEN` | @BotFather в Telegram |
| `TELEGRAM_CHAT_ID` | запустить `python3 get_chat_id.py` |

## Архитектура

Оба скрипта используют одну и ту же цепочку:

```
RSS-ленты → keyword filter → score_article() → AI (Groq) → Telegram
```

**Скоринг** (`score_article`) — чисто ключевые слова, без AI-запросов, используется как фолбэк. Основной скоринг — структурированный AI-вызов `score_article_ai()` из `news_pipeline.py` (0-5 + reason + summary). Порог: и `monitor.py`, и `notifier.py` отправляют/показывают статьи с оценкой ≥ 3.

**AI-анализ** — Groq API, модели:
- `notifier.py`, `monitor.py`, `bot.py`, `news_pipeline.py` → `openai/gpt-oss-120b` (reasoning-модель, `reasoning_effort="low"`)

Историческая справка: llama-4-scout и llama-3.3-70b удалены из Groq (сентябрь 2026) — все вызовы переведены на gpt-oss-120b, иначе generate_post молча отдаёт фолбэк.

**Фолбэк**: если `GROQ_API_KEY` не задан, оба скрипта работают только на keyword-скоринге без AI-описаний.

Общая инфраструктура (новые источники, полнотекстовая экстракция, структурированный AI-скоринг, дедупликация) вынесена в `news_pipeline.py`, который импортируют `monitor.py`, `notifier.py` и `bot.py`. `KEYWORDS`/`HIGH_VALUE` остаются продублированы в `monitor.py`/`notifier.py` — единственное, что по-прежнему нужно синхронизировать вручную.

## Ключевые слова и тематика

Канал Zerocoder — аудитория: специалисты по **ИИ и вайбкодингу**. Термин «no-code» в текстах постов не используется — актуальная повестка канала: вайбкодинг.

При добавлении новых ключевых слов обновлять в **обоих файлах** (`monitor.py` и `notifier.py`) — списки `KEYWORDS` и `HIGH_VALUE` должны быть синхронизированы.

`HIGH_VALUE` — ключевые слова удвоенного веса: ChatGPT, Claude, GPT, LLM, Gemini, OpenAI, Anthropic, вайбкодинг, no-code и др.

Отдельная приоритетная ниша для аудитории — практический тулинг ИИ: `skill`/`скил`/`скилы` (в т.ч. `agent skills`), `prompt`/`промпт`/`промты`, `mcp`, `lifehack`/`лайфхак`/`лайфхаки` — тоже в `HIGH_VALUE`.

## Дайджест (`notifier.py`)

Каждые 2 часа — **один пост-дайджест** вместо поста на каждую новость:

```
<b>📊 Дайджест к этому часу</b>

<b>💡 Заголовок пункта</b>
1-2 предложения сути
🔗 Источник: <url>   (📎 «Оригинальный пост» — если источник начинается с «X:», т.е. это твит)

…до 5 пунктов…

<CTA>
```

Конвейер `main()`: выборка горячих (как раньше, но верхние 5 — `DIGEST_MAX_ITEMS`) → `generate_digest()` (один AI-вызов, JSON `{items: [{n, headline, text}], cta}`, пункт привязан к статье по номеру `n`) → `fact_check_digest()` → `assemble_digest_post()` → один `send_to_telegram()`, все URL отправленных пунктов пишутся в `sent_urls.txt`.

**Фактчекинг перед отправкой** (`fact_check_digest()`):
- **Сверка с текстом статьи**: полный текст (уже извлечён при скоринге, лежит в `_full_text`) — AI вердикт по каждому пункту: `ok` / `uncertain` (текст переписывается только из подтверждённых фактов) / `wrong` (пункт выбрасывается). Известный риск галлюцинации фактов («Space X AI») закрыт этим шагом.
- **Веб-корроборация** (keyless): фактчекер заодно придумывает `query` — по нему `news_pipeline.fetch_google_news()` ищет, пишут ли о том же другие СМИ за 24ч; ≥2 уникальных издателей из заголовков («… - РБК») → пункт `corroborated` (в логе ✓, в пост не помечается). Тишина — не блокер.

Если фактчекинг выбросил все пункты — пост не отправляется (только лог). Без `GROQ_API_KEY` — фолбэк: дайджест из голых заголовков + ссылки, без AI и фактчекинга.

Готовый пост на одну новость по-прежнему доступен через `/post <ссылка>` в `bot.py` (`generate_post()` — 1 заголовок → ссылка → тело → 1 CTA, маркеры `ЗАГОЛОВОК:`/`ТЕЛО:`/`CTA:` парсит `_parse_sections()`). Команды `/news2`, `/news24`, `/news7`, `/reddit` — облегчённый формат (заголовок + короткое описание от AI + источник + ссылка).

**Формула подачи** (`_CONTENT_FORMULA`) — по разбору того, что реально заходит аудитории:
- Заходит: конкретный вау-результат «здесь и сейчас», эффект открытия («так можно было?!»), живая история с деталями, лёгкая подача.
- Не заходит: описательный пересказ без вывода, пересказ уже известного, тяжёлые абзацы-лекции, пассивный призыв в духе «подписывайтесь» или «делитесь мнением» без конкретного повода.

CTA дайджеста — одна лёгкая концовка-вопрос на весь пост (без нажима, без искусственной поляризации).

**Правила естественного текста** (`_NATURAL_TEXT_RULES`): простые слова и короткие предложения, без ИИ-штампов и канцелярита («раскрыть потенциал», «революционный», «трансформационный», «оптимизировать», «разблокировать возможности», «инновационный», «прорывной»). Вместо этого — «вот как это работает», «вот что я нашла», «но есть проблема». Продублированы в системных сообщениях Groq-запросов и применяются и к дайджесту, и к `/post`.

`clean_text()` убирает: иероглифы, польские диакритики, слова с перемешанной латиницей и кириллицей (`specialistам`), исправляет слипшиеся заглавные, правит написание брендов (`Open AI` → `OpenAI`).

## Автоматические рутины (claude.ai/code/routines)

| Рутина | ID | Расписание |
|---|---|---|
| AI News Digest — Daily | `trig_0146BWUC6AVE7F8trPuiY7pA` | 9:00 МСК ежедневно |
| AI News Notifier — Hourly | `trig_011j3PkWwJk4kdLH9kDtMyxd` | каждые 2 часа |

Рутины скачивают скрипты через `curl` из публичного GitHub-репо (не `git clone` — блокируется в облаке Anthropic). После изменений в коде рутины подхватывают новую версию автоматически при следующем запуске.

Если рутина отключилась с причиной `auto_disabled_repo_access` — это значит что в `sources` осталась ссылка на git-репо. Убрать через `RemoteTrigger update` с `"sources": []`.

Если рутины снова включат, `curl` должен скачивать `news_pipeline.py` вместе с `monitor.py`/`notifier.py` — без него импорт `import news_pipeline` в обоих скриптах упадёт.
