# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Автоматический мониторинг ИИ-новостей для контент-менеджера Telegram-канала **Zerocoder** (тематика: ИИ и вайбкодинг). Два режима работы:

- **`monitor.py`** — ежедневный дайджест в 9:00 МСК, отправляется в Telegram
- **`notifier.py`** — каждые 2 часа один пост «📊 Дайджест к этому часу»: до 5 горячих новостей кратко, с фактчекингом перед отправкой

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env  # заполнить ключи

python3 monitor.py        # дайджест за последние 24ч
python3 monitor.py 48     # дайджест за 48ч
python3 notifier.py       # собрать дайджест горячих новостей за 24ч (запускается каждые 2ч)
```

## Переменные окружения (`.env`)

| Переменная | Где взять |
|---|---|
| `GROQ_API_KEY` | console.groq.com (бесплатно) |
| `TELEGRAM_BOT_TOKEN` | @BotFather в Telegram |
| `TELEGRAM_CHAT_ID` | запустить `python3 get_chat_id.py` |
| `TELEGRAM_AUTO_SEND` | рубильник автоотправки: не задан или не `1` — ничего не отправлять (только лог), `1` — возвращать отправку |

## Архитектура

Оба скрипта используют одну и ту же цепочку:

```
RSS-ленты → keyword filter → score_article() → AI (Groq) → Telegram
```

**Скоринг** (`score_article`) — чисто ключевые слова, без AI-запросов, используется как фолбэк. Основной скоринг — структурированный AI-вызов `score_article_ai()` из `news_pipeline.py` (0-5 + reason + summary). Порог: и `monitor.py`, и `notifier.py` отправляют/показывают статьи с оценкой ≥ 3.

**AI-анализ** — Groq API, модели:
- `notifier.py`, `monitor.py`, `bot.py`, `news_pipeline.py` → `openai/gpt-oss-120b` (reasoning-модель, `reasoning_effort="low"`)

Историческая справка: llama-4-scout и llama-3.3-70b удалены из Groq (сентябрь 2026) — все вызовы переведены на gpt-oss-120b, иначе generate_post молча отдаёт фолбэк.

**Фолбэк**: если `GROQ_API_KEY` не задан, оба скрипта работают только на keyword-скоринге без AI-описаний.

Общая инфраструктура (новые источники, полнотекстовая экстракция, структурированный AI-скоринг, дедупликация) вынесена в `news_pipeline.py`, который импортируют `monitor.py`, `notifier.py`, `bot.py` и `editorial.py`. `KEYWORDS`/`HIGH_VALUE` остаются продублированы в `monitor.py`/`notifier.py` — единственное, что по-прежнему нужно синхронизировать вручную.

## Ключевые слова и тематика

Канал Zerocoder — аудитория: специалисты по **ИИ и вайбкодингу**. Термин «no-code» в текстах постов не используется — актуальная повестка канала: вайбкодинг.

При добавлении новых ключевых слов обновлять в **обоих файлах** (`monitor.py` и `notifier.py`) — списки `KEYWORDS` и `HIGH_VALUE` должны быть синхронизированы.

`HIGH_VALUE` — ключевые слова удвоенного веса: ChatGPT, Claude, GPT, LLM, Gemini, OpenAI, Anthropic, вайбкодинг, no-code и др.

Отдельная приоритетная ниша для аудитории — практический тулинг ИИ: `skill`/`скил`/`скилы` (в т.ч. `agent skills`), `prompt`/`промпт`/`промты`, `mcp`, `lifehack`/`лайфхак`/`лайфхаки` — тоже в `HIGH_VALUE`.

## Источники

RSS (5 лент, списки `FEEDS` в `monitor.py` и `notifier.py` синхронизированы): OpenAI Blog, Google AI Blog, DeepMind Blog, HuggingFace Blog, Simon Willison. Historically Zerocoder, ZDNet и Forbes AI / TechCrunch AI / Karpathy / One Useful Thing / DAIR AI убраны по решению редактора (окт 2026).

Дополнительно, через `news_pipeline.py` (все keyless, без API-ключей):
- **Hacker News** — топ-истории с `score ≥ 100` (Firebase API).
- **GitHub Trending** — через `api.ossinsight.io`, языки Python/TypeScript/All, `min_stars ≥ 5`.
- **Google News RSS search** — по запросам из `GOOGLE_NEWS_QUERIES` («вайбкодинг», «Claude Code», «AI coding agent»).
- **Reddit** — 5 сабреддитов (`REDDIT_SUBREDDITS`: LocalLLaMA, Singularity, OpenAI, ClaudeAI, vibecoding) через Atom-ленту `/new/.rss`, 3с паузы между запросами.
- **Telegram-каналы** (19 шт., `TELEGRAM_CHANNELS` в `news_pipeline.py`) — **обходятся по решению редактора (2026-10-14)**: `fetch_telegram_channels` не вызывается ни в `monitor.py`, ни в `notifier.py`, ни в `bot.py`. Функция и список каналов в `news_pipeline.py` сохранены — можно вернуть одним вызовом. Раньше их посты участвовали в дедупликации `buzz` (см. `_is_hot` в `notifier.py`) — сейчас эффектbuzz возможен только от СМИ/Google News.

## Дайджест (`notifier.py`)

Каждые 2 часа — **один пост-дайджест** вместо поста на каждую новость:

```
<b>📊 Дайджест к этому часу</b>

<b>💡 Заголовок пункта</b>
1-2 предложения сути
🔗 Источник: <url>   (📎 «Оригинальный пост» — если источник начинается с «X:», т.е. это твит)

…до 5 пунктов…

<CTA>
```

Конвейер `main()`: выборка горячих (как раньше, но верхние 5 — `DIGEST_MAX_ITEMS`) → `generate_digest()` (один AI-вызов, JSON `{items: [{n, headline, text}], cta}`, пункт привязан к статье по номеру `n`) → `fact_check_digest()` → `assemble_digest_post()` → один `send_to_telegram()`, все URL отправленных пунктов пишутся в `sent_urls.txt`.

**Фактчекинг перед отправкой** (`fact_check_digest()`):
- **Сверка с текстом статьи**: полный текст (уже извлечён при скоринге, лежит в `_full_text`) — AI вердикт по каждому пункту: `ok` / `uncertain` (текст переписывается только из подтверждённых фактов) / `wrong` (пункт выбрасывается). Известный риск галлюцинации фактов («Space X AI») закрыт этим шагом.
- **Веб-корроборация** (keyless): фактчекер заодно придумывает `query` — по нему `news_pipeline.fetch_google_news()` ищет, пишут ли о том же другие СМИ за 24ч; ≥2 уникальных издателей из заголовков («… - РБК») → пункт `corroborated` (в логе ✓, в пост не помечается). Тишина — не блокер.

Если фактчекинг выбросил все пункты — пост не отправляется (только лог). Без `GROQ_API_KEY` — фолбэк: дайджест из голых заголовков + ссылки, без AI и фактчекинга.

Готовый пост на одну новость по-прежнему доступен через `/post <ссылка>` в `bot.py` (`generate_post()` — 1 заголовок → ссылка → тело → 1 CTA, маркеры `ЗАГОЛОВОК:`/`ТЕЛО:`/`CTA:` парсит `_parse_sections()`). Команды `/news2`, `/news24`, `/news7`, `/reddit` — облегчённый формат (заголовок + короткое описание от AI + источник + ссылка); отбор у них мягче — score ≥ 2, это обзор по запросу, а не автоматическая отправка.

**Формула подачи** (`_CONTENT_FORMULA`) — по разбору того, что реально заходит аудитории:
- Заходит: конкретный вау-результат «здесь и сейчас», эффект открытия («так можно было?!»), живая история с деталями, лёгкая подача.
- Не заходит: описательный пересказ без вывода, пересказ уже известного, тяжёлые абзацы-лекции, пассивный призыв в духе «подписывайтесь» или «делитесь мнением» без конкретного повода.

CTA дайджеста — одна лёгкая концовка-вопрос на весь пост (без нажима, без искусственной поляризации).

**Правила естественного текста** (`_NATURAL_TEXT_RULES`): простые слова и короткие предложения, без ИИ-штампов и канцелярита («раскрыть потенциал», «революционный», «трансформационный», «оптимизировать», «разблокировать возможности», «инновационный», «прорывной»). Вместо этого — «вот как это работает», «вот что я нашла», «но есть проблема». Продублированы в системных сообщениях Groq-запросов и применяются и к дайджесту, и к `/post`.

`clean_text()` убирает: иероглифы, польские диакритики, слова с перемешанной латиницей и кириллицей (`specialistам`), исправляет слипшиеся заглавные, правит написание брендов (`Open AI` → `OpenAI`).

## Карточки для редактора (`editorial.py`)

Команды бота `/digest` и `/card` — редакторская работа по инструкции от 2026-10-12: бот не постит сам, а готовит тему и полную карточку, решение всегда за человеком. Не автоотправка — рубильник `TELEGRAM_AUTO_SEND` их не гейтит. Спека: `docs/superpowers/specs/2026-10-12-editorial-cards-design.md`.

**Источники** (`EDITORIAL_FEEDS`, все keyless): 4 RSS-блога (OpenAI, Google AI, DeepMind, HuggingFace Blog) + Hacker News + GitHub Trending + Product Hunt (`feed?category=artificial-intelligence`) + GitHub Blog + HF trending (`fetch_hf_trending`, у записей нет даты — отображается «трендинг на момент сбора, без даты выхода»). **Не входят**: Zerocoder, Google News, ZDNet, Simon Willison, Reddit, Telegram-каналы, arXiv — это фильтр только нового редакторского пайплайна, старые системы (`monitor.py`/`notifier.py`) не тронуты.

**Конвейер `/digest [часы]`** (окно 2–168ч, по умолчанию 24): `collect_topics()` (сбор → `dedup_cross_source` → keyword-фильтр → кап по keyword-баллу, `CANDIDATE_CAP=15`) → `select_topics()` (полнотекстовая экстракция → AI-скоринг → список ≤ 8) → `render_topic_list()`.

**Скоринг по 6 критериям** (`score_topic_ai`): новизна, польза, удивление, актуальность, пересылка, соответствие — каждый 0–2, `total` всегда пересчитывается кодом из критериев (число модели игнорируется), max 12. Пороги: ≥ 9 — приоритет, ≥ 6 — в списке, < 6 — отброшено. Рубрика «Инфоповод-пустышка» отбрасывает тему. Ошибка AI на отдельной статье — фолбэк на keyword-оценку (`ai=False`, порог списка ≥ 1). Без `GROQ_API_KEY` весь список строится на keyword-оценках с пометкой «режим без AI».

**Карточка `/card N`** (`build_card` — один AI-вызов по полному тексту): тема, рубрика, оценка, формат поста (А–Е), суть, почему интересно, для кого, риски, 3 варианта заголовка, визуальная идея, черновик (заголовок + тело 3–4 абзаца + CTA, отдельным сообщением — чтобы копировать), до 6 проверяемых утверждений (`claims`). Карточка кэшируется (`get_or_build_card` — повторный `/card` не жжёт второй AI-вызов), хранится в `bot_data` до перезапуска бота; URL уже показанной темы попадает в `editorial_seen_cards` и выпадает из следующих `/digest` (`filter_unseen`).

**Фактчекинг черновика** (`fact_check_card`) — поверх механики дайджеста из `notifier.py` (та же схема вердиктов `ok`/`uncertain`/`wrong` через `_parse_factcheck_json`): ok → в «подтверждённые», uncertain → корроборация через `fetch_google_news` (≥2 издателей → пометка «✓ (подтверждено другими СМИ)», ссылки → «Доп. источники», ≤ 3, свой URL исключён), wrong → убирается из черновика (фактчекер переписывает тело). Длинные сообщения режутся по абзацам до 4096 знаков (`_split_by_paragraphs`), всё `html.escape`.

## Дайджест инструментов для вайбкодеров (`tools_digest.py`)

Команда бота `/tools [часы]` — подборка до 5 бесплатных инструментов, которые русскоязычный вайбкодер может попробовать сам (не только AI-сервисы: CLI, расширения, скрипты, конструкторы). Окно по умолчанию 168ч, аргумент 6–720. Не автоотправка — только в чат с ботом, `TELEGRAM_AUTO_SEND` её не гейтит. Спека: `docs/superpowers/specs/2026-10-15-tools-digest-design.md`.

**Источники** (все keyless, через `news_pipeline`): HN (`min_score=50`, акцент на «Show HN»), GitHub Trending, HF trending, Reddit (LocalLLaMA, opensource, SideProject, vibecoding, ClaudeAI), Product Hunt (`fetch_producthunt`), DEV.to (`fetch_dev_to`, теги ai и aitools), awesome-каталоги (`fetch_awesome_lists`: taskade/awesome-vibe-coding, yeaight7/awesome-ai-devtools — парсинг markdown-строк `- [Name](url) — desc`).

**Конвейер**: `collect_tools()` (слияние → `dedup_cross_source` → keyword-фильтр по расширенному `TOOL_KEYWORDS`, кап 40 по баллу с весами `TOOL_KEYWORD_WEIGHTS`) → `prepare_candidates()`/`fetch_official_page()` (полнотекстовая экстракция + для GitHub-репо README/лицензия/последний релиз через keyless GitHub API; неудачная проверка НЕ отбрасывает кандидата, а помечает `uncertain`) → `select_tools()` (один Groq-вызов, JSON с вердиктами ok/uncertain/wrong) → `build_tools_messages()` (3 блока: источники проверки, готовый пост, примечания — каждый ≤ 4096).

**Правила из редакторской инструкции зашиты в `_TOOLS_SYSTEM_RULES`**: 5 категорий бесплатности (полностью бесплатный / open-source / free tier / демо-период / локальная версия), «не проверено» → не выдумывать, разнообразие категорий (не 5 конструкторов подряд), запрет рекламных штампов (`_NATURAL_TEXT_RULES`). `wrong` отсеивается кодом (url запоминается в `rejected` и не всплывает снова); `uncertain` — с пометкой «требует уточнения».

**Кэш** (`get_or_build_tools`): `bot_data["tools_cache"]` — повторный `/tools` без аргумента возвращает кэш, другое окно — пересбор; `bot_data["tools_seen"]` — url всех AI-оценённых инструментов исключаются из следующих прогонов. Кандидатов на AI уходит ≤ 20 из собранных. Без `GROQ_API_KEY` — фолбэк: голый список кандидатов с пометкой «режим без AI» (описания из RSS, без заявлений о бесплатности). Мало проверенных (< 3) — явный warning «недостаточно». GitHub API без токена: ~42 запроса на прогон, лимит 60/ч — при 403 кандидат получает `uncertain`.

## Автоматические рутины (claude.ai/code/routines)

Автоотправка целиком гейтится `TELEGRAM_AUTO_SEND` (см. выше): без `1` рутинные прогоны скачивают скрипты, собирают выборку и **молча пишут дайджест в лог, ничего не отправляя** — и дайджесты, и алерты (`news_pipeline.send_alert` тоже проверяет рубильник). Команды бота (`/news24`, `/post`, `/rewrite`...) работают по запросу независимо от рубильника.

| Рутина | ID | Расписание |
|---|---|---|
| AI News Digest — Daily | `trig_0146BWUC6AVE7F8trPuiY7pA` | 9:00 МСК ежедневно |
| AI News Notifier — Hourly | `trig_011j3PkWwJk4kdLH9kDtMyxd` | каждые 2 часа |

Рутины скачивают скрипты через `curl` из публичного GitHub-репо (не `git clone` — блокируется в облаке Anthropic). После изменений в коде рутины подхватывают новую версию автоматически при следующем запуске.

Если рутина отключилась с причиной `auto_disabled_repo_access` — это значит что в `sources` осталась ссылка на git-репо. Убрать через `RemoteTrigger update` с `"sources": []`.

Если рутины снова включат, `curl` должен скачивать `news_pipeline.py` вместе с `monitor.py`/`notifier.py` — без него импорт `import news_pipeline` в обоих скриптах упадёт.
